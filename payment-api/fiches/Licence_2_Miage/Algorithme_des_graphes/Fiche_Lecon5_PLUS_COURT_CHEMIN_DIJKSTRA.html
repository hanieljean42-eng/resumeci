📖 Algorithme des graphes 🏫 Licence 2 MIAGE — Semestre 3 Leçon 5 : Plus court chemin — Dijkstra

I. Le problème

Plus court chemin : dans un graphe pondéré, trouver le trajet de coût minimal (temps, distance, argent…) entre un sommet de départ et un sommet d'arrivée. Ex. classique : trajet routier le plus rapide entre deux villes.

II. L'algorithme de Dijkstra

Principe : algorithme glouton conçu pour des valuations positives. Un sommet de départ x est fixé. On construit progressivement un ensemble de sommets pour lesquels on connaît le plus court chemin depuis x.
Règle d'or : à chaque étape, on choisit le sommet dont la distance à x est minimale parmi ceux qui n'ont pas encore été choisis. On recommence tant qu'il reste des sommets à sélectionner.

Déroulement pas à pas

  1. Initialisation : d(x) = 0 ; d(tous les autres sommets) = +∞. Le sommet x entre dans l'ensemble S des sommets « fixés ».
  2. À chaque itération : parmi les sommets non fixés, choisir celui de distance minimale → il entre dans S (sa distance est maintenant définitive).
  3. Relaxation : pour chaque voisin v du sommet u qui vient d'être fixé, si d(u) + w(u,v) < d(v), alors mettre à jour d(v) = d(u) + w(u,v) et retenir u comme prédécesseur de v.
  4. Arrêt : quand le sommet cible est fixé (ou tous les sommets atteignables sont dans S).
Lecture du résultat : la distance minimale est d(cible) ; le trajet se reconstitue en remontant les prédécesseurs depuis la cible jusqu'à x.

III. Application — TD Graphes n°1

Énoncé : un automobiliste doit aller de A à C en utilisant les durées moyennes (en minutes) d'un graphe pondéré orienté (sens uniques). Déterminer le trajet le plus rapide ; le retour est-il plus rapide que l'aller ?

Méthode :
  1. Identifier le sens des arcs (sens uniques → chemins possibles limités) ;
  2. Appliquer Dijkstra depuis A : fixer les sommets par distance croissante ;
  3. Noter à chaque étape la distance et le prédécesseur ;
  4. À l'arrivée en C : remonter les prédécesseurs → trajet optimal et temps minimal.

Point clé du TD : comme le graphe est orienté, le trajet retour C → A peut être différent (voire impossible) — ne pas supposer la symétrie du temps de parcours.

IV. ⚠️ Pièges d'examen

⚠️ Pièges classiques :
  • Appliquer Dijkstra avec des valuations négatives → l'algorithme n'est pas garanti (réservé aux poids positifs).
  • Oublier qu'un graphe orienté n'est pas symétrique : le trajet retour n'est pas le trajet aller inversé.
  • Choisir le prochain sommet au hasard au lieu de prendre la distance minimale — c'est tout le principe glouton.
  • Ne pas mettre à jour d(v) quand un chemin plus court est trouvé via un autre sommet.
  • Confondre « plus court chemin » (nombre d'arêtes) et « plus rapide/cheap chemin » (somme des poids) — Dijkstra optimise le poids total.
