I. Les sous-langages SQL

Sous-langageRôleCommandes
LDD (DDL)Définir la structure : tables, contraintes, index, vuesCREATE, ALTER, DROP, TRUNCATE
LMD (DML)Manipuler les données (lignes)INSERT, UPDATE, DELETE, MERGE
LID (DQL)Interroger les données (sans les modifier)SELECT

II. CREATE TABLE et contraintes

CREATE TABLE filiere (
  id      INT PRIMARY KEY,
  libelle VARCHAR(50) NOT NULL
);

CREATE TABLE inscription (
  etudiant_id INT NOT NULL,
  cours_id    INT NOT NULL,
  note        DECIMAL(4,2),
  PRIMARY KEY (etudiant_id, cours_id),
  FOREIGN KEY (etudiant_id) REFERENCES etudiant(id) ON DELETE CASCADE,
  FOREIGN KEY (cours_id)    REFERENCES cours(id)
);
  • PRIMARY KEY : identifie de façon unique chaque ligne ;
  • FOREIGN KEY ... REFERENCES : lie à une clé primaire d'une autre table ;
  • ON DELETE : CASCADE (supprime les lignes dépendantes), SET NULL (met la FK à NULL), RESTRICT/NO ACTION (refuse la suppression) ;
  • NOT NULL, UNIQUE, DEFAULT, CHECK : autres contraintes.

Variante : CREATE TABLE nouvelle AS SELECT ... (copie structure + données).

III. INSERT / UPDATE / DELETE

-- Insertion
INSERT INTO etudiant (id, nom, prenom, date_naissance, email, filiere_id)
VALUES (1, 'KOUASSI', 'Jean', DATE '2004-03-15', 'j@ex.ci', 1);

INSERT INTO inscription (etudiant_id, cours_id)
SELECT id, 10 FROM etudiant WHERE filiere_id = 1;   -- insertion depuis un SELECT

-- Modification : SANS WHERE → TOUTES les lignes !
UPDATE inscription SET note = 18 WHERE cours_id = 10 AND note < 19;

-- Suppression
DELETE FROM inscription WHERE note IS NULL;
Règle d'or : un UPDATE ou DELETE sans clause WHERE modifie/supprime toutes les lignes de la table.

IV. MERGE (upsert)

Upsert : « insert or update » — insère une ligne ou la met à jour si la clé existe déjà. Syntaxe très différente selon le SGBD :
MERGE INTO inscription i
USING (SELECT 101 AS etudiant_id, 10 AS cours_id, 15.5 AS note FROM dual) s
ON (i.etudiant_id = s.etudiant_id AND i.cours_id = s.cours_id)
WHEN MATCHED     THEN UPDATE SET i.note = s.note
WHEN NOT MATCHED THEN INSERT (etudiant_id, cours_id, note)
                   VALUES (s.etudiant_id, s.cours_id, s.note);
  • MySQL : INSERT ... ON DUPLICATE KEY UPDATE ;
  • PostgreSQL : INSERT ... ON CONFLICT (...) DO UPDATE SET ... = EXCLUDED.... ;
  • Oracle : MERGE INTO ... USING ... ON ....

V. Multi-SGBD : points de vigilance

  • Oracle : pas de IF NOT EXISTS (avant 23ai), FROM dual requis pour SELECT sans table, pas de ON UPDATE dans les FK ;
  • MySQL/PostgreSQL : CREATE DATABASE/SCHEMA, autocommit par défaut ;
  • Littéraux de date : ISO '2004-03-15' ou Oracle DATE '2004-03-15' / TO_DATE(...).

VI. ⚠️ Pièges d'examen

⚠️ Pièges classiques :
  • Confondre LDD (structure) et LMD (données) : CREATE = LDD, INSERT/UPDATE/DELETE = LMD, SELECT = LID.
  • Oublier le WHERE sur UPDATE/DELETE → mise à jour/suppression globale.
  • Mettre une FK vers une colonne non unique ou non PK → violation de contrainte.
  • Confondre ON DELETE CASCADE (supprime tout) et SET NULL (annule le lien).
  • Utiliser la syntaxe upsert d'un SGBD sur un autre (ON DUPLICATE KEY = MySQL, ON CONFLICT = PostgreSQL, MERGE = Oracle).
