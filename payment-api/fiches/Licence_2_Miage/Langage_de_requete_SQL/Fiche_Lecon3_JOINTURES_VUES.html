I. Les jointures

Jointure : combine les lignes de plusieurs tables selon une condition — généralement l'égalité entre une clé étrangère et une clé primaire. La norme SQL-92 écrit la condition dans JOIN ... ON (à préférer au WHERE).
SELECT ...
FROM table1 [alias1]
  { [INNER] JOIN | LEFT [OUTER] JOIN | RIGHT [OUTER] JOIN | FULL [OUTER] JOIN }
  table2 [alias2] { ON condition | USING (colonne [, ...]) }

Les types de jointure

JointureLignes retournées
INNER JOINSeulement les lignes ayant une correspondance des deux côtés
LEFT [OUTER] JOINToutes les lignes de gauche ; NULL à droite si pas de correspondance
RIGHT [OUTER] JOINToutes les lignes de droite ; NULL à gauche si pas de correspondance
FULL [OUTER] JOINToutes les lignes des deux tables
CROSS JOINProduit cartésien : chaque ligne de A × chaque ligne de B
NATURAL JOINJointure sur les colonnes de même nom
Auto-jointureUne table jointe avec elle-même via deux alias

II. Opérateurs ensemblistes

requete1 { UNION [ALL] | INTERSECT | EXCEPT | MINUS } requete2 [ORDER BY ...];
  • UNION : union de deux résultats (doublons supprimés) ; UNION ALL : conserve les doublons ;
  • INTERSECT : lignes présentes dans les deux ;
  • EXCEPT (MINUS sous Oracle) : lignes de la 1re absentes de la 2e.

III. Sous-requêtes, CTE et vues

A. Sous-requêtes

Requête imbriquée dans une autre requête : dans le SELECT (colonne calculée), le FROM (table dérivée), le WHERE (EXISTS, IN, comparaison).

B. CTE (Common Table Expression)

WITH nom_cte AS (
  SELECT ... FROM ... WHERE ...
)
SELECT ... FROM nom_cte JOIN ...;

Table temporaire nommée, définie dans la requête — améliore la lisibilité et permet le chaînage de plusieurs CTE.

C. Les vues

Vue : table virtuelle définie par une requête SELECT — n'utilise pas de données propres, présente une vision filtrée/simplifiée des tables de base. Avantages : simplification, sécurité (colonnes masquées), réutilisabilité.
CREATE VIEW vue_moyennes AS
SELECT cours_id, AVG(note) AS moyenne
FROM inscription GROUP BY cours_id;

IV. Index et transactions

  • Index : structure (arbre B+) accélérant la recherche sur une colonne — CREATE INDEX idx ON table(col) ; à créer sur les colonnes de jointure/fréquemment filtrées ; coût : ralentit INSERT/UPDATE ;
  • Transactions : ensemble d'opérations atomiques — BEGIN / COMMIT / ROLLBACK ; toutes réussissent ou toutes annulées (ACID).

V. TP d'application (TP3/TP4)

Les TP fournis appliquent : SELECT avec filtres WHERE (TP3), puis fonctions Oracle (TP4 : NVL, TO_CHAR, TRUNC, SYSDATE…).

VI. ⚠️ Pièges d'examen

⚠️ Pièges classiques :
  • Confondre LEFT JOIN et RIGHT JOIN : LEFT garde toutes les lignes de la table de gauche (NULL à droite si pas de match).
  • Penser que CROSS JOIN filtre → c'est un produit cartésien (toutes les combinaisons).
  • Oublier UNION ALL vs UNION : ALL conserve les doublons.
  • Mettre la condition de jointure dans le WHERE pour une outer join → transforme en inner join ; la condition va dans le ON.
  • Confondre vue (requête stockée, pas de données) et table.
  • Confondre sous-requête et CTE : la CTE est nommée et réutilisable dans la requête.
