I. Qu'est-ce qu'une DTD ?

DTD (Document Type Definition / Définition de type de document) : modèle décrivant la grammaire d'un document XML — syntaxe d'organisation des balises + contraintes sémantiques (structure, valeurs applicables). Vérification faite par le parseur XML.

Pourquoi utiliser une DTD ?

  • Déclarer de nouvelles balises et spécifier des contraintes ;
  • Permettre à une application de savoir quel document XML produire et quoi lire ;
  • Assurer l'interopérabilité entre applications (règles d'échange communes) ;
  • Valider les flux XML entrants d'un programme.

DTD interne ou externe

FormeDescription
InterneDéfinie dans le document XML, entre crochets de la balise DOCTYPE
ExterneRéférencée (nom + URL) dans le prologue via <!DOCTYPE racine SYSTEM "fichier.dtd">

Les deux peuvent coexister ; en cas de doublon, c'est la DTD interne qui est prioritaire.

III. Les entités

Entité : « raccourci » pour insérer du contenu — caractères spéciaux, texte répété, références externes.
  • Entités prédéfinies : &amp; (&), &lt; (<), &gt; (>), &quot; («), &apos; (') ;
  • Entité de caractère : &#201; = É ;
  • Entité générale : <!ENTITY nom "valeur"> puis &nom; dans le document ;
  • Entité paramétrique : <!ENTITY % nom "valeur"> — utilisée dans la DTD elle-même (ex. %contenu; dans un modèle de contenu) ;
  • Entité externe : référence un fichier (texte ou binaire via NOTATION).

IV. Les attributs

<!ATTLIST élément attribut type_contrainte valeur_par_défaut>
ContrainteSignification
#REQUIREDAttribut obligatoire
#IMPLIEDAttribut optionnel (peut être absent)
#FIXED "valeur"Valeur fixe obligatoire
"valeur"Valeur par défaut si l'attribut est absent

Types d'attributs

  • CDATA : texte libre ;
  • ID : identifiant unique dans tout le document ;
  • IDREF / IDREFS : référence à un ID (un ou plusieurs) ;
  • NMTOKEN : nom sans espace ;
  • Type énuméré : (val1|val2|val3) — valeurs autorisées + valeur par défaut possible.

V. Les namespaces (espaces de noms)

Recommandation W3C permettant de combinater plusieurs vocabulaires XML sans conflit de noms — en préfixant les éléments par un espace de noms déclaré : xmlns:prefixe="URI". Indispensable car les DTD ne supportent pas les namespaces.

VI. Exemple type (sujet d'examen)

  • Inscription : attributs etudiant IDREF, cours IDREF → relient une inscription à un étudiant et un cours définis par ID ;
  • Note : décimal entre 0 et 20 ; session : énumération (normale|rattrapage).

VII. ⚠️ Pièges d'examen

⚠️ Pièges classiques :
  • Confondre ? (0-1), * (0-n) et + (1-n) — + exige au moins une occurrence.
  • Mettre une virgule dans un modèle de contenu → impose un ordre strict ; | = choix sans ordre.
  • Oublier de déclarer un sous-élément du modèle de contenu → document non valide.
  • Confondre entité générale (&nom; dans le document) et paramétrique (%nom; dans la DTD).
  • #IMPLIED ≠ valeur par défaut : IMPLIED = attribut optionnel sans valeur par défaut ; "valeur" = défaut si absent.
  • Oublier que ID doit être unique dans tout le document, IDREF doit pointer vers un ID existant.
