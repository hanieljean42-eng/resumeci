I. Historique : de SGML à XML

ÉtapeContenu
HTML / HTTPÀ l'origine, un document HTML mêlait à parts égales données et présentation — la présentation a fini par dominer
EDIFACTNorme d'échange de données informatisées (EDI) pour l'administration, le commerce et le transport, sous l'égide de l'ONU (fin années 1980)
SGML (ISO 8879)Standard Generalized Markup Language — utilisé en gestion documentaire ; trop complexe
1996Le W3C + industriels simplifient SGML
XML 1.0Publié en février 1998 (XML 1.1 en 2004). Méta-langage à balises pour décrire et échanger des données structurées
Principes hérités de SGML : séparation présentation/données, structuration des données, description des structures par schémas (DTD).

II. XML vs HTML et JSON

  • XML ≠ HTML : XML ne possède pas de balises prédéfinies, c'est un langage à balises extensible ; il décrit la structure logique des données sous forme d'arbre hiérarchique.
  • XML vs JSON : JSON est un format de données simple et léger ; XML est plus robuste, flexible et strict (validation par DTD/XSD, namespaces, typage).
  • XML différencie structure, contenu et présentation (cette dernière via XSL/XSLT).

III. Champs d'application

Échanges de données inter-entreprises (EDI), configuration d'applications, multimédia (MPEG-7), intégration d'applications d'entreprise (EAI, adaptateurs XML), bases de données (Oracle utilise XML pour décrire ses schémas), dialogue client/serveur HTTP.

IV. Structure d'un document XML

PartieDescription
PrologueEn-tête optionnel : déclaration XML + déclaration DOCTYPE
CorpsUn élément racine unique contenant des sous-éléments imbriqués (arbre)
Commentaires<!-- ... --> — ignorés par l'analyseur

Déclaration XML (prologue)

<?xml version="1.0" encoding="UTF-8" standalone="no"?>
  • version : par défaut "1.0" ;
  • encoding : jeu de caractères accepté dans le document ;
  • standalone="yes" : document autonome (aucune DTD externe) ; "no" : référence une DTD externe via DOCTYPE.
<!DOCTYPE racine SYSTEM "fichier.dtd" [ ...déclarations internes... ]>

V. Règles d'un document bien formé

6 types de balisage : balises (ouvrantes/fermantes/vides), références d'entités, commentaires, sections CDATA, prologue + DOCTYPE, instructions de traitement.
  • Au moins 1 élément, jamais vide ;
  • Un seul élément racine (point de départ unique) ;
  • Imbrication correcte : aucun chevauchement — un élément ne se ferme que si tous ses sous-éléments sont fermés ;
  • Références d'entités elles-mêmes bien formées ;
  • Données : pas de &, >, ^ bruts — utiliser les entités (&amp;, &lt;, &gt;, &#201; pour É…) ;
  • Sensible à la casse : nom d'élément identique dans balise ouvrante et fermante.

VI. Analyseur XML (parseur)

L'analyseur lit le document, vérifie qu'il est bien formé et le convertit en structure arborescente ; les entités sont remplacées par leur contenu. Le résultat est transmis à une application (navigateur, programme…).

VII. ⚠️ Bien formé ≠ valide

Bien formé : syntaxiquement correct (règles ci-dessus).
Valide : document bien formé ET conforme aux contraintes du document type (DTD ou XSD).

VIII. ⚠️ Pièges d'examen

⚠️ Pièges classiques :
  • Dire « XML = HTML » ou « XML a des balises prédéfinies » → faux : XML est extensible, sans balises prédéfinies.
  • Confondre bien formé et valide : valide ⇒ bien formé, mais pas l'inverse.
  • Oublier la sensibilité à la casse ou l'imbrication stricte (pas de chevauchement).
  • Croire que XML est « ancien » : XML 1.0 date de 1998 ; SGML = ISO 8879.
  • Écrire & brut dans une donnée → doit être échappé &amp;.
