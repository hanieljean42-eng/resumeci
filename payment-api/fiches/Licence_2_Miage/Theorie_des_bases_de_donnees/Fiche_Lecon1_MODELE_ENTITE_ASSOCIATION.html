📖 Théorie des bases de données 🏫 Licence 2 MIAGE — Semestre 3 Leçon 1 : Modèle Entité-Association

I. Notions de base

  • Base de données : ensemble organisé d'informations structurées, stockées et accessibles ;
  • SGBD (Système de Gestion de Bases de Données) : logiciel gérant le stockage, l'accès et la manipulation des données — exemples : MySQL, Microsoft Access / SQL Server, PostgreSQL ;
  • Modèle relationnel : les données sont organisées sous forme de relations/tableaux pouvant être liés entre eux ; une relation = en-tête + corps.

II. Le modèle Entité-Association (E/A)

La conception d'une BD suit 2 étapes : (1) construire un schéma conceptuel modélisé en entités et associations ; (2) transformer ce schéma E/A en schéma relationnel (MLR).

Entités

  • Choses (objets) — regroupement des choses de même nature : classes d'entités et classes d'association ;
  • Propriété d'une entité = attribut ;
  • Identifiant : propriété qui identifie de façon unique chaque occurrence d'entité (ex. CIN pour Personne, IdAuteur pour Auteur — le nom seul ne suffit pas : homonymes possibles).

Associations

  • Lien entre deux ou plusieurs entités ;
  • Degré K = nombre d'entités participantes : K=1 → unaire/récursive (ex. « être parent »), K=2 → binaire, K=3 → ternaire ;
  • Exemple : 1,1 Livre — 1,n Édite — 1,n Éditeur, Auteur 1,n Écrit 1,1 Livre.

III. Les cardinalités

La cardinalité mesure le degré de participation d'une entité à une association — lue dans le sens de lecture du diagramme.
CardinalitéSignification
0,1Au moins zéro, au plus 1
0,nAu moins zéro, au plus n
1,1Au moins 1, au plus 1 (obligatoire et unique)
1,nAu moins 1, au plus n (obligatoire, plusieurs possibles)
  • Cardinalités minimales : 0 et 1 ; maximales : 1 et n ;
  • Exemple lu : « Un client achète un ou plusieurs produits » → côté Client : 1,n ; « un produit est acheté par aucun ou plusieurs clients » → côté Produit : 0,n.

IV. Exemple type

Personne (Id_Personne, Nom, Prénom)
   │ 0,n  Possède  0,1
   ▼                    ▼
Voiture (Num_Série, Marque, Carburant)
   ▲
Fabricant (Id_Fabricant) — 1,n Fabrique 1,1 Voiture

Ex-2 du cours : « Un auteur peut-il écrire plusieurs livres ? » Oui — la cardinalité 1,n côté Auteur le permet. « Des auteurs homonymes ? » Oui, car le nom n'est pas identifiant — seul IdAuteur l'est.

V. ⚠️ Pièges d'examen

⚠️ Pièges classiques :
  • Confondre entité (classe d'objets) et attribut (propriété) et identifiant (clé unique).
  • Lire une cardinalité dans le mauvais sens : elle se lit du côté de l'entité participante vers l'association.
  • Confondre cardinalité minimale (0 ou 1 = optionnel/obligatoire) et maximale (1 ou n = unique/multiple).
  • Utiliser le nom comme identifiant → les homonymes le rendent insuffisant.
  • Oublier que la conception suit E/A → MLR : d'abord le schéma conceptuel, puis la traduction relationnelle.
