📖 Algorithme de base 🏫 Licence 1 MIAGE — Semestre 1 Leçon 4 : Les sous-programmes (procédures, fonctions, récursivité)

I. Pourquoi des sous-programmes ?

Sous-programme : bloc de code prêt à l'emploi permettant d'éviter d'écrire plusieurs fois le même code. Deux formes : la procédure et la fonction.
  • Procédure : ensemble d'instructions référencé par un nom ; l'exécution est provoquée par le simple énoncé du nom. Ne renvoie pas de valeur.
  • Fonction : sous-programme au sens mathématique : elle calcule et retourne une valeur (une image).
Fonction successeur(x : entier) : entier
Début retourner(x + 1) Fin
Appel : Afficher x, "+1 =", successeur(x) — l'appel est remplacé par la valeur retournée.

II. Variables globales et locales

Variable globaleVariable locale
DéclaréeDans la partie déclarative du programme principalDans la partie déclarative d'un sous-programme
PortéeValable dans tout le programme (principal + sous-programmes)Limitée au sous-programme qui la déclare
Important : les variables du programme appelant ne sont pas lisibles depuis un sous-programme — il faut les communiquer par passage de paramètres.

III. Paramètres et passage de paramètres

  • Paramètre effectif : variable (souvent globale) dont la valeur est effectivement utilisée — c'est la valeur transmise à l'appel.
  • Paramètre formel (muet) : paramètre écrit entre parenthèses dans la déclaration ; il reçoit son contenu du paramètre effectif.
Passage par valeurPassage par adresse
Ce qui est transmisLa valeur du paramètre effectif (une copie)L'adresse du paramètre effectif (la variable elle-même)
DéclarationProcedure echange(x, y : entier)Procedure echange(x^, y^ : entier)
Appelechange(A, B)echange(@A, @B)
EffetModifie des copies : A et B inchangées à la sortieModifie les originaux : A et B réellement échangées
⚠️ Piège classique : la procédure echange(x, y) par valeur échange les copies x et y, mais A et B restent inchangées. Pour modifier les variables d'origine → passage par adresse.
Le type de la valeur retournée n'est précisé que pour les fonctions, jamais pour les procédures.

IV. La récursivité

Récursivité : possibilité de faire figurer dans la définition d'un objet une référence à cet objet lui-même. Une fonction/procédure récursive s'appelle elle-même et intègre une variable de contrôle permettant d'arrêter le processus.
Exemple — somme des n premiers entiers :
Som(n) = n + Som(n − 1), avec le cas d'arrêt Som(1) = 1
  • Toute fonction récursive exige un cas de base (condition d'arrêt) — sinon boucle infinie.

V. ⚠️ Pièges d'examen

⚠️ Pièges classiques :
  • Croire qu'un passage par valeur modifie la variable d'appel : non, seule une copie est modifiée.
  • Utiliser une variable locale en dehors de son sous-programme : elle est invisible ailleurs.
  • Écrire une fonction sans retourner : elle doit renvoyer une valeur.
  • Récursivité sans cas d'arrêt → boucle infinie.
  • Confondre paramètre formel (déclaration) et effectif (appel).
💡 Réflexe : besoin de modifier la variable appelante ? → passage par adresse (^ / @). Besoin seulement d'une valeur en entrée ? → passage par valeur suffit et protège les données.
