I. Qu'est-ce qu'un projet ?

Définition (ISO 10006) : « un processus unique, constitué d'un ensemble d'activités coordonnées et maîtrisées, comportant des dates de début et de fin, entrepris dans le but d'atteindre un objectif défini avec des moyens adaptés ».
Caractéristiques : temporaire (début/fin), unique (livrable spécifique), structuré en phases (initiation, planification, exécution, clôture), objectif mesurable.
CritèreProjetActivité
DuréeTemporairePermanente / récurrente
ObjectifLivrable uniqueFonctionnement continu
OrganisationPar phasesRoutine / opérations
ExempleDévelopper un site e-commerceGérer les commandes quotidiennes du site
Spécificités des projets informatiques : complexité technique (multiples technologies), évolution rapide (obsolescence), intangibilité (livrables immatériels : logiciels, BDD), interdépendance (développeurs, analystes, utilisateurs), risque élevé (sécurité, délais, coûts).

II. Le système d'information (SI)

SI : ensemble organisé de ressources permettant de collecter, traiter, stocker et diffuser l'information.
4 composantes : ① Matériel (ordinateurs, serveurs, réseaux) · ② Logiciels (applications, bases de données) · ③ Données (informations brutes et traitées) · ④ Utilisateurs (personnes qui exploitent le système).
Rôle : soutenir la prise de décision, améliorer la communication, automatiser les processus.

III. Le triangle de la gestion de projet

3 contraintes interdépendantes :
• Coût : budget alloué (ressources financières, humaines, matérielles)
• Délai : temps disponible pour réaliser le projet
• Qualité : niveau de performance et de conformité attendu
Règle d'or : améliorer l'une impacte forcément les deux autres. Réduire le délai → ↑ coût ou ↓ qualité ; réduire le coût → ↑ délai ou ↓ qualité ; ↑ qualité → + de temps et/ou de budget. Le chef de projet doit prioriser et arbitrer.

IV. Le cycle de vie d'un projet — 5 phases et leurs livrables

PhaseObjectifs / activitésLivrables
1. InitialisationDéfinir le besoin et la justification ; identifier les parties prenantes ; première vision des objectifs et contraintesCharte de projet (objectifs, périmètre, budget, acteurs clés) ; cahier des charges ; analyse de faisabilité (technique, économique, organisationnelle)
2. PlanificationDécomposer le projet en tâches ; définir délais, ressources, coûts ; identifier les risquesPlan de management (PMP) ; planning détaillé (Gantt, PERT, MPM) ; backlog produit ; plan de communication et de gestion des risques
3. ExécutionRéaliser les tâches ; mobiliser les ressources ; produire les livrables intermédiairesCode source versionné, documentation technique, rapports de tests, builds/démos, rapports d'avancement
4. Suivi et contrôleVérifier la conformité planification/exécution ; mesurer la performance (coût, délai, qualité) ; corriger les dérivesTableaux de bord (KPI, burndown chart) ; rapports de contrôle qualité ; comptes rendus ; plans de correction
5. ClôtureLivrer le produit fini ; évaluer la satisfaction ; capitaliser les leçons apprisesRapport de clôture ; retour d'expérience (REX) ; livrables finaux ; guide utilisateur ; attestation de livraison
À retenir : chaque phase produit des livrables qui servent de jalons pour mesurer l'avancement et décider de la poursuite. Le suivi/contrôle se déroule en parallèle de l'exécution, pas après.

V. ⚠️ Pièges d'examen

⚠️ Pièges classiques :
  • Projet ≠ activité : le critère décisif est temporaire + unique. « Gérer les congés » = activité ; « déployer un SGRH » = projet.
  • Ne pas oublier une des 4 composantes du SI : matériel, logiciel, données, utilisateurs (souvent oubliée).
  • Le triangle : citer les trois contraintes ET leur interdépendance — une définition seule ne suffit pas.
  • Ajouter une fonctionnalité en cours de projet affecte d'abord coût et délai, puis la qualité si l'ajout est précipité.
  • La charte de projet appartient à la phase d'initialisation, pas à la planification.
