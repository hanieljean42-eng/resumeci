I. Dépendance fonctionnelle (DF)

DF : une propriété (ou ensemble) P2 dépend fonctionnellement de P1 si la connaissance de la valeur de P1 détermine une et une seule valeur de P2. Notée P1 → P2 (« P2 dépend de P1 » ou « P1 détermine P2 »).
Exemples : numSecu → nomPers (un n° de sécu détermine un seul nom) — mais un prénom ne détermine rien. DF composée : numEtudiant, numModule, numSession → valeurNote. Un identifiant détermine par DF toutes les autres propriétés de son objet/association.

Types de DF

  • DF élémentaire (DFE) : aucune partie de P1 ne détermine P2 — tout P1 est nécessaire à la détermination.
  • DF élémentaire directe (DFED) : il n'existe pas de propriété z telle que x → z et z → y (on élimine les DF obtenues par transitivité).

Propriétés mathématiques des DF

RègleFormuleExemple
TransitivitéP1→P2 et P2→P3 ⟹ P1→P3Ref → code_tva et code_tva → taux donc Ref → taux
RéflexivitéP1→P1Matricule → Matricule
ProjectionP1→(P2+P3) ⟹ P1→P2 et P1→P3NumProf → Nom + discipline
AugmentationP1→P2 ⟹ P1+P3→P2Ref → Pu donc Ref + désignation → Pu (⚠️ la DF cesse d'être élémentaire)
AdditivitéP1→P2 et P1→P3 ⟹ P1→(P2+P3)Ref → Pu + désignation

II. DF entre entités et CIF

DF entre entités : il existe une DF O1 → O2 entre deux objets liés par une association si chaque occurrence de O1 n'est associée qu'à au plus une occurrence de O2 — révélée par des cardinalités (0,1) ou (1,1). O1 = objet source, O2 = objet but. La DF est forte pour (1,1) et faible pour (0,1).
Règles : une DF forte n'est pas porteuse de propriétés — si elle en porte, celles-ci doivent migrer sur l'objet source. Une DF révèle une relation de type « est un ». DF possible aussi entre sous-ensembles d'entités d'une association (ex. Prof + Horaire → Classe).
Contrainte d'intégrité fonctionnelle (CIF) : un objet est totalement identifié par la connaissance d'un ou plusieurs autres objets au sein d'une même association.

III. Graphe des DF et couvertures

GDF (Graphe des Dépendances Fonctionnelles) : représentation de toutes les DF entre propriétés et entre entités du SI. Construction : recenser les propriétés non calculées et non concaténées → déterminer les DF → les propriétés en origine de flèches = identifiants → traiter les propriétés isolées par DF composées.
  • Fermeture transitive / couverture maximale : le GDF enrichi de toutes les DF perceptibles (ex. Code_fournisseur → code_pays → pays, donc Code_fournisseur → pays).
  • Couverture minimale / SAT (Structure d'Accès Théorique) : le GDF dénué de toute DF transitive — on ne garde que les DF directes.

IV. Normalisation des entités (formes normales)

FormeCondition
1FNPossède un identifiant + aucune propriété à valeurs multiples
2FNEn 1FN + toutes les DF entre propriétés sont élémentaires (sinon redondance : ex. « moyenne » dépendant d'une partie de l'identifiant → sortir dans une association MOYENNE)
3FNEn 2FN + toutes les DF sont directes (pas de DF transitive : ex. code_postal → département → nom_département → créer un objet DEPARTEMENT)
BCFNEn 3FN + les seules DFE sont celles où une clé détermine un attribut (sinon décomposer : ex. professeur → matière alors que la clé est (matière, classe))

V. Normalisation des associations

Règle : si une propriété dépend fonctionnellement de l'identifiant d'une entité, elle doit se trouver dans cette entité — pas dans l'association. Exemple : « droit-payé » dépend de façon fonctionnelle et élémentaire de code-etud → rapatrier dans l'entité ETUDIANT.

VI. ⚠️ Pièges d'examen

⚠️ Pièges classiques :
  • Sens de la DF : P1 → P2 = P1 détermine P2 (et non l'inverse).
  • DF forte = cardinalité (1,1) ; une DF forte ne porte pas de propriétés.
  • Couverture minimale ≠ fermeture : la couverture minimale supprime les transitives.
  • Violation 2FN = DF non élémentaire ; violation 3FN = DF non directe ; violation BCFN = DFE dont la source n'est pas une clé.
