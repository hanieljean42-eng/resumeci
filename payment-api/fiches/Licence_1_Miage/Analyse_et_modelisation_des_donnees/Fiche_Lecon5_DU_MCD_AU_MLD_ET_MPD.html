I. Pourquoi le MLD ?

Modèle Logique des Données (MLD) : modèle qui représente le contenu d'un MCD sous le formalisme des tables logiques, adapté aux structures d'une base de données. Le MCD ne connaît pas la notion de table ; la base de données ne connaît ni classes ni cardinalités — le MLD fait le pont.
Différence clé : le MCD représente le SI de façon indépendante du système informatique ; le MLD tient compte de la réalisation via un SGBD. Choix techniques possibles : SGBD relationnel, Codasyl, objet, ou fichier classique.

II. Règles de transformation MCD → MLD

Règle de base : les entités

Toute entité → une table. Les propriétés → attributs de la table ; l'identifiant → clé primaire (soulignée) ; les occurrences → enregistrements (lignes).
Ex. : Entreprise (NoEntreprise, nom, adresse, codePostal, Localité)

Cas des associations binaires (x,1 / x,n)

  • Relation (0,1)/(1,1) ↔ (0,n)/(1,n) : l'identifiant de l'objet côté (x,n) migre comme attribut (clé étrangère) dans la table issue de l'objet côté (x,1). Les propriétés de la relation suivent le même chemin.
Ex. : REGION(nom_region) et DEPARTEMENT(num_dept, nom_dept, #nom_region) — la clé de REGION migre dans DEPARTEMENT (notée # = clé étrangère).

Cas des associations plusieurs-à-plusieurs (x,n / x,n)

  • Chaque objet → une table (identifiant → clé primaire).
  • La relation → une table dont la clé primaire est la concaténation des identifiants des objets participants.
Ex. : ELEVE(matricule, nom, prénoms), MATIERE(matiere), DEVOIR(numéro, matricule, matiere, note), MOYENNE(matricule, matiere, moyenne).

Cas des associations un-à-un (x,1 / x,1)

Les deux objets → deux tables ; l'identifiant d'un objet migre dans l'autre comme clé étrangère, selon la contrainte de dépendance fonctionnelle.
Ex. : PAYS(Code-PAYS, Nom), CAPITAL_POLITI(Code_cap, Nom_cap, #Code-PAYS).

III. Le MPD (Modèle Physique des Données)

MPD : description du niveau physique des données — directement exploitable par le système de gestion de données choisi. Il n'existe pas d'approche normalisée : le MPD dépend du choix technique.
SolutionMLD associéMPD : ce qui est géré
SGBD CodasylMLD Codasyl (sets)Gestion physique des sets via pointeurs ; description des sets
SGBD relationnelMLD relationnel (tables)Gestion transparente prise en charge par le SGBD ; description des tables
SGF classiqueMLD fichierGestion physique complète à la charge du réalisateur (pointeurs, clés d'accès secondaires) ; description des fichiers
Chaîne complète : MCD → MLD (selon le type de SGBD) → MPD (tables, fichiers, index…). Le MPD est le modèle « le plus proche de la machine ».

IV. ⚠️ Pièges d'examen

⚠️ Pièges classiques :
  • Sens de migration : c'est l'identifiant du côté (x,n) qui migre vers la table du côté (x,1) — jamais l'inverse.
  • Association n-n : la relation devient une table avec clé primaire composée (concaténation des identifiants).
  • Oublier de souligner la clé primaire et de préfixer la clé étrangère (#).
  • Confondre MLD (formalisme tables, indépendant du SGBD précis) et MPD (dépendant du choix technique).
