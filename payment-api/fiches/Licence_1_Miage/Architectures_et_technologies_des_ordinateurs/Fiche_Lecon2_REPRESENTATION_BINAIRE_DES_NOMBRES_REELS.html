I. Écriture binaire d'un nombre réel

En décimal, les chiffres après la virgule sont des dixièmes, centièmes… En binaire, ce sont des demis, quarts, huitièmes… — puissances de 2 négatives : 2−1, 2−2, 2−3…

Ex. : (1,1101)₂ = 1 + 1/2 + 1/4 + 1/16 = 1,8125.

1. Conversion base 2 → base 10

Additionner les puissances de 2 : (101,1101)₂ = 2² + 2⁰ + 2−1 + 2−2 + 2−4 = 4 + 1 + 0,5 + 0,25 + 0,0625 = 5,8125

2. Conversion base 10 → base 2

  • Partie entière : divisions par 2 classiques → 5 = (101)₂.
  • Partie décimale : multiplications successives par 2, sans reporter la partie entière ; les parties entières (0 ou 1) lues de haut en bas donnent les chiffres binaires.
0,8125 → 0,8125×2 = 1,625 ; 0,625×2 = 1,25 ; 0,25×2 = 0,5 ; 0,5×2 = 1 → 0,8125 = (0,1101)₂ donc 5,8125 = (101,1101)₂
⚠️ Écritures infinies : certains réels ont un développement binaire infini périodique — 1,2 = (1,001100110011…)₂. Impossible à représenter exactement en machine.

II. La norme IEEE 754

Représentation en virgule flottante : les réels sont codés sous la forme s · m × 2ⁿ, inspirée de l'écriture scientifique (±m × 10ⁿ avec mantisse m ∈ [1 ; 10[).
FormatSigneExposantMantisseDécalage
Simple précision (binary32)1 bit8 bits23 bits+127
Double précision (binary64)1 bit11 bits52 bits+1023
  • Signe s : 0 pour +, 1 pour −.
  • Mantisse : en base 2, m ∈ [1 ; 2[ donc m = 1,xxxx… — le « 1 » initial n'est pas codé (implicite) ; seuls les bits après la virgule sont stockés.
  • Exposant : entier relatif codé sans complément à 2 : on lui ajoute le décalage (127 ou 1023) pour obtenir un entier positif.
Exemple complet — 5,8125 = (101,1101)₂ = (1,011101 × 2²)₂
→ signe = 0 · exposant = 2 + 127 = 129 = (10000001)₂ · mantisse = 01110100…0
Mot 32 bits : 0 | 10000001 | 01110100000000000000000

III. Une représentation approximative

Les nombres réels à écriture binaire infinie sont tronqués : la mantisse tient sur 23 ou 52 bits → le flottant stocké n'est qu'une approximation du réel.
  • Ex. : 1,2 → mantisse infinie (0011…) tronquée à 23 bits → le flottant « 1.2 » ≠ réel 1,2.
  • Trous dans les flottants : en double précision, il n'existe aucun flottant entre 1.5 et 1.5000000000000002 (précision ≈ 2−52 ≈ 2 × 10−16).
⚠️ À retenir absolument :
  • Les flottants sont une représentation approximative des réels.
  • Il est impossible de représenter exactement tous les réels en machine.
  • Additions/soustractions de flottants peuvent donner des résultats surprenants.
  • Ne jamais tester l'égalité entre deux flottants (utiliser une tolérance ε).

IV. ⚠️ Pièges d'examen

⚠️ Pièges classiques :
  • Oublier de normaliser la mantisse : elle doit toujours commencer par « 1, » (intervalle [1 ; 2[).
  • Coder l'exposant en complément à 2 : la norme utilise un décalage (+127 / +1023).
  • Inverser l'ordre de lecture des multiplications par 2 : les chiffres se lisent de haut en bas (première partie entière obtenue = premier chiffre après la virgule).
  • Confondre les tailles : simple = 1+8+23 = 32 bits ; double = 1+11+52 = 64 bits.
💡 Réflexe exercice : pour coder un réel → 1) signe ; 2) écrire en binaire ; 3) normaliser (1,xxx × 2ⁿ) ; 4) exposant + 127 ; 5) mantisse sans le « 1 » complétée à 23 bits par des zéros.
