📖 Architectures et technologies des ordinateurs 🏫 Licence 1 MIAGE — Semestre 1 Leçon 3 : La fonction de communication — bus, interfaces et gestion des entrées-sorties

I. Vue d'ensemble

Fonction de communication : toutes les activités permettant les échanges d'informations entre périphériques, processeur central et mémoire centrale — c'est la gestion des entrées-sorties. Fonction complexe : si elle est mal réalisée, elle pénalise toutes les performances de l'ordinateur.

Acteurs :

  • Périphériques : dispositifs d'entrée/sortie (clavier, souris, imprimante, écran, modem) ou de stockage permanent (disques magnétiques), pilotés par des signaux électriques spécifiques.
  • Contrôleur (unité d'échange) : pilote un périphérique et gère ses accès au bus ; convertit le flux de bits numériques en signaux électriques.
  • Bus de communication : transporte les informations entre composants.
  • Pilote (driver) : programme du système d'exploitation gérant les E/S d'un périphérique. Les applications ne parlent aux périphériques qu'à travers leur pilote — on peut changer d'imprimante sans modifier le traitement de texte.
Appel système : un ordre d'E/S dans un programme est traduit en SVC (Supervisor Call / trappe système) → bascule vers le pilote du système d'exploitation. Mécanisme à la base des systèmes multiprogrammés.

II. Les bus

Bus : ensemble de « fils » reliant les composants. Indicateur clé : la bande passante = fréquence × largeur du bus.
  • Bus parallèles : autant de fils que de bits — simples mais coûteux et peu fiables sur longue distance.
  • Bus série : une seule voie, bits sérialisés — grandes distances.
  • Architecture à bus unique : source de goulet d'étranglement (composants hétérogènes) ; les conflits d'accès sont arbitrés par l'arbitre de bus, avec priorité au contrôleur → mécanisme de vol de cycle (le processeur est privé du bus pendant le transfert).

III. Interfaces d'accès aux périphériques

1. L'unité d'échange (contrôleur)

  • Adressage : intégrée à l'espace d'adressage du processeur — on l'adresse comme un banc mémoire.
  • Structure : registre d'état (état du périphérique, ex. « plus de papier ») + registre de données (échanges mémoire ↔ périphérique). Chaque registre est adressable.
  • Double nature : communique en numérique avec processeur/mémoire (registres via bus) et en signaux électriques avec le périphérique.
  • Exemples : UART (liaison série + modem RTC), contrôleurs de disques IDE/EIDE/ATA (cylindre, face, lecture/écriture — ATA/33 = 33 Mo/s, ATA/66 = 66 Mo/s en mode DMA), cartes graphiques (mémoire d'image bitmap + plans mémoire + table de couleurs + convertisseurs DAC RVB).

IV. Les trois modèles de gestion des entrées-sorties

Préalable — basculement de contexte : quand le pilote prend le relais du programme utilisateur, le contexte matériel (registres, compteur ordinal) du programme est sauvegardé en mémoire, puis restitué à la reprise.
ModèlePrincipeProcesseur
1. Liaison programméeLe pilote boucle en lisant le registre d'état tant que le périphérique est occupé (attente active), écrit chaque caractère dans le registre de donnéesTotalement occupé pendant l'E/S — inefficace : les performances suivent le périphérique
2. E/S pilotées par interruptionsL'unité d'échange émet une interruption quand le périphérique est prêt ; entre deux interruptions le processeur retourne au programme utilisateurLibre sauf pendant le traitement de l'interruption → « tâche de fond »
3. E/S asynchrones — DMADirect Memory Access : composant dédié (registres d'adresse, de comptage, de commande + tampon + mini-processeur) transfère mémoire ↔ périphérique sans le CPU ; interruption seulement en fin de transfertTotalement libre pendant le transfert → rend possible la multiprogrammation

V. ⚠️ Pièges d'examen

⚠️ Pièges classiques :
  • Croire que le programme utilisateur pilote le périphérique : il passe par le pilote du système d'exploitation (via SVC).
  • Confondre vol de cycle (arbitre de bus, priorité au contrôleur) et DMA (transfert mémoire direct sans CPU).
  • Dire que la liaison programmée libère le processeur : c'est l'inverse — attente active.
  • Oublier que l'interruption arrive en fin d'opération E/S (ou à chaque caractère selon le mode).
💡 Réflexe : chaîne d'une impression = application → SVC → pilote → bus → contrôleur (registres) → signaux électriques → périphérique. La progression historique : attente active → interruptions → DMA.
