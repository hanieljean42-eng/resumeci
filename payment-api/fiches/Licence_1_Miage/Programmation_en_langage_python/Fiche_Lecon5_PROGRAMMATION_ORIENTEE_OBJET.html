I. Terminologie

Classe : nouveau type de données — un « moule » ou une « usine » à objets (ex. list, str).
Objet / instance : exemplaire particulier produit par une classe ([3,5,1] est une instance de list).
objet = attributs + méthodes : les données (attributs) + les fonctions applicables (méthodes). L'encapsulation embarque les propriétés dans l'objet et évite les variables globales.
UML : langage graphique de conception (diagramme de classes pour concevoir classes et relations).

II. Classes et instanciation

class C:
    """Documentation.""";
    x = 23       # attribut de CLASSE (partagé par toutes les instances)
    def affiche(self):  # méthode — self = référence de l'objet courant
        self.z = 42  # attribut d'INSTANCE (propre à l'objet)

Instanciation : a = C() — on appelle la classe comme une fonction.
• a.x lit l'attribut de classe (23) ; a.x = 12 crée un attribut d'instance qui masque celui de classe — C.x reste 23 !
• Langage dynamique : on peut ajouter des attributs à la volée (C.z = 6, a.y = 44)
• Attributs de classe accédés via C.x dans les méthodes ; d'instance via self.z.
Espaces de noms : les classes lisent les globales mais ne les modifient pas ; les instances lisent les attributs de classe mais doivent passer par C.x pour les modifier. Règle LGI pour les noms non qualifiés ; un nom qualifié (obj.attr) est cherché dans l'objet puis dans ses classes.

III. Méthodes spéciales

Méthodes spéciales : noms prédéfinis entourés de doubles soulignés (__init__, __str__, __add__…). Elles servent à : initialiser l'objet, modifier son affichage, surcharger les opérateurs.
__init__(self, …) : initialisateur appelé automatiquement à l'instanciation — crée les attributs d'instance avec leurs valeurs initiales ; ne retourne rien.
__str__ : chaîne « utilisateur » affichée par print() ; __repr__ : représentation « machine ».
Surcharge des opérateurs : __add__ (obj1 + obj2), __sub__ (−), __mul__ (*), __div__/__truediv__ (/), __floordiv__ (//), __neg__ (opposé), __len__, __iter__, __call__.
Ex. : class Vecteur2D avec __add__ → v1 + v2 fait l'addition vectorielle ; __str__ → print(v1) affiche « Vecteur(1.2, 2.3) ».

IV. Héritage et polymorphisme

Héritage : créer une classe fille à partir d'une classe préexistante (super-classe) dont elle hérite tous les attributs et méthodes, avec des fonctionnalités supplémentaires ou différentes — class Fille(Mere):.
Polymorphisme par dérivation : des méthodes de même nom dans des classes héritées distinctes effectuent des travaux différents — l'objet s'adapte dynamiquement. Le développeur programme génériquement : l'objet « sait » quelle méthode exécuter.
Ex. : class QuadrupedeDebout(Quadrupede) redéfinit piedsAuContactDuSol() — même appel, comportement adapté au type réel de l'objet.

V. Conception orientée objet

ConceptionRelationImplémentation
Association« a-un » ou « utilise-un » (une Voiture a-un Moteur) — peut être étiquetée avec des multiplicitésIntégrer d'autres objets dans le constructeur de la classe conteneur (attribut de type objet)
Dérivation (héritage)« est-un » (un Ion est-un Atome)class Ion(Atome): — la fille hérite et spécialise
Réflexe de conception : « est-un » → héritage ; « a-un » → association (attribut objet). Les deux cohabitent souvent.

VI. ⚠️ Pièges d'examen

⚠️ Pièges classiques :
  • self est obligatoire en 1ᵉʳ paramètre de chaque méthode — mais on ne le passe pas à l'appel (obj.m(x)).
  • a.x = 12 ne modifie PAS l'attribut de classe : il crée un attribut d'instance qui le masque.
  • __init__ ≠ constructeur au sens strict : c'est un initialisateur automatique, sans valeur de retour.
  • print(obj) appelle __str__ ; sans elle, affichage <__main__.C object at 0x…>.
  • Héritage = « est-un » ; composition/association = « a-un » — confusion classique en examen de conception.
  • Attribut de classe modifiable partagé (ex. une liste) : modifié via une instance → visible partout !
