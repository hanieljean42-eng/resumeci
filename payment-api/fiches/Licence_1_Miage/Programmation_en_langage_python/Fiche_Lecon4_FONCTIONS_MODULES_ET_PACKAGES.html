I. Définition et syntaxe

Fonction : ensemble d'instructions regroupées sous un nom, exécutées à la demande — une « mise en facteur commun » du code répété.
Avantages : évite la duplication · met en relief entrées/sorties · réutilisable via l'import · décompose une tâche complexe.
Syntaxe : def nomFonction(p1, p2): + docstring (conseillée) + bloc indenté. Bloc vide → pass. Sans return, la fonction retourne implicitement None (procédure). return a, b = retour multiple (tuple).

II. Passage des arguments

Mécanisme : passage par affectation — chaque paramètre de l'appel est affecté à l'argument de la définition, dans l'ordre. On peut aussi nommer les paramètres à l'appel : table(base=7, debut=2, fin=8).
Une fonction peut être passée en paramètre (une variable peut référencer une fonction) : h(f, 3) appelle f(3).
NotationRôleExemple
def f(a, b=2)Valeur par défaut — paramètres optionnels en fin de listeaccueil("Student", "Joe") utilise les défauts
def f(*args)Nombre arbitraire d'arguments → reçus comme tuple (dernière position)somme(23, 42, 13)
def f(**kwargs)Arguments nommés arbitraires → reçus comme dictionnaire (toute dernière position)unDict(a=23, b=42)
f(*seq) à l'appelDécompresse une séquence en paramètressomme(*(2,4,6)) → 12
f(**d) à l'appelDécompresse un dictionnaire en paramètres nommésunDict(**{'a':1})
⚠️ Valeur par défaut modifiable : jamais def f(liste=[]) — la liste est partagée entre appels ! Utiliser def f(liste=None) puis if liste is None: liste = [].

III. Espaces de noms et portée

Portée : région où un nom est visible. Globale = niveau module (dictionnaire globals()) ; locale = intérieur d'une fonction (locals()) ; interne = fonctions standard.
Règle LGI : la recherche d'un nom se fait Locale → Globale → Interne.
Cas pratiques :
• Variable utilisée en lecture dans une fonction : trouvée en global si pas de locale — x=99; fonc() lit x → OK
• x = 3 dans la fonction crée un x local qui masque le global (le global reste 99)
• Pour modifier un global : première instruction global x → x += 2 modifie le vrai x global.

IV. Modules et packages

Module : fichier script Python (.py) définissant des éléments réutilisables (fonctions, classes, variables). Avantages : réutilisation, doc/tests intégrés, partage de services, partition de l'espace de noms. Le module machin = fichier machin.py.
Imports :
• import math → accès via l'espace de noms : math.sin(x) — le module n'est chargé qu'une fois
• from math import sin, pi → accès direct aux noms choisis : sin(x)
• Ordre conseillé : bibliothèque standard → bibliothèques tierces → modules personnels
• Variables globales à modifier : passer par module.variable pour garantir l'unicité.
Auto-test : la variable spéciale __name__ vaut '__main__' si le fichier est le module principal, son nom sinon → idiom : if __name__ == "__main__": pour un bloc exécuté seulement en lancement direct (tests de la bibliothèque).
Package : dossier regroupant plusieurs modules. Bibliothèque standard : +200 modules « piles comprises » : math, sys, re, string, struct, textwrap, difflib, copy…

V. ⚠️ Pièges d'examen

⚠️ Pièges classiques :
  • Oublier return → la fonction retourne None (pas une erreur, mais un résultat vide).
  • *args = tuple, **kwargs = dict ; l'ordre dans la définition : paramètres → *args → **kwargs.
  • Affecter dans une fonction crée une variable locale même si un global porte le même nom → global x nécessaire pour modifier.
  • from m import * : importe tous les noms — pollution de l'espace de noms, à éviter.
  • Le paramètre d'une fonction recevant une liste partage la référence : la modifier à l'intérieur modifie l'objet de l'appelant.
  • def f(l=[]) : la liste par défaut persiste entre les appels — bug classique.
